# Constitution Evidence: French documentary retrieval over the 2011 Moroccan Constitution

**Status:** development report, 2026-10-18. This is not a final evaluated release. The French OCR has not been checked article by article against the source PDF, the planned 180-family benchmark is not reviewed, and no human answer judgments exist. All numerical retrieval results below are provisional diagnostics. The Arabic track was excluded at the project owner's request.

## 1. Problem and scope

The application helps a French-speaking reader find passages in Morocco's 2011 Constitution and inspect the PDF pages behind them. It can return verbatim extracts or ask a locally hosted Qwen model for a structured answer with exact citations. The application does not determine current case law, implementing law, litigation outcomes, or legal advice. A passage that contains the same words as a question may still fail to support the conclusion the user wants. This distinction is the central quality risk: source linkage is necessary for inspectability, but exact quotation alone is not legal or semantic validation.

The source is the 28-page [Maroc.ma institutional PDF](https://maroc.ma/sites/default/files/2024-10/constitution_du_1er_juillet_2011.pdf), edition 2011. Its configured source URL and acquisition metadata are in `configs/corpus.json`; the local PDF has SHA-256 `4101d45b4733a6b36eee77bd9ef4175b23160103089b003b13907e8b6d59333d`. The URL's upload directory is not treated as a constitutional revision. The downloaded PDF is not checked into Git. Its redistribution rights have not been established by this project, so reproduction instructions fetch it from the institutional source instead of republishing it.

## 2. Corpus and provenance

The source PDF is an image scan. The ingestion pipeline obtains page text with Poppler when possible and French Tesseract OCR otherwise; it then parses a preamble and 180 numbered articles. It stores page-aware article text, paragraph passages, canonical offsets, text hashes, and physical PDF page spans. `constitution-evidence validate-corpus` checks inventory, passage parentage, offsets, hashes, and page relationships. A correction file can apply only page-anchored OCR edits with source and raw-page hashes. No unverified correction has been asserted. The audit report provides the PDF pages and OCR text side by side for later review.

The current generated corpus has 181 units including the preamble and 633 passages. The article file hash is `8a80b613971b6b7ffde76cefea14e582a289738546356a15c446ee10854eeb90`; the passage file hash is `2b7c534cbc06db05526bf95c17fbeb27460d329191e45f4a5a34f54eab590dd1`. Both are recorded in the ignored `data/processed/manifest.json`, which explicitly says `unreviewed_ocr`. These hashes identify this development corpus, not a reviewed transcription. Article inventory checks cannot catch every lost negation, incorrect number, or boundary error.

The data card in `docs/data-card.md` separates the institution's PDF, derived OCR, and author-written provisional questions. It also records what is excluded from Git. A future corpus release needs article-by-article PDF comparison, a correction log, fresh hashes, and review status set through a documented process. Until then, extractive answers remain labeled partial and model claims are marked semantically unverified.

## 3. System design

Lexical search uses BM25S with Lucene-style BM25. Dense search uses FastEmbed ONNX embeddings and an exact FAISS cosine index. Hybrid search combines lexical and dense candidate rankings with reciprocal rank fusion, with an optional FastEmbed cross-encoder reranker. Direct article-number and preamble questions have explicit lookup. A one-hop reference expander follows article references found in retrieved text and records their source passage and exact quoted reference; it never recursively traverses a legal graph. An optional bounded decomposition searches the original question plus at most two focused subquestions. None of these options is presented as inherently better than a simpler search.

Context packing enforces character budgets before generation. The extractive path returns exact snippets and PDF page links. The local Qwen adapter talks only to a loopback llama.cpp server, requests structured JSON, and checks that every claimed citation names a supplied passage, carries the correct hash and offsets, and exactly matches the cited text. Its `unverified_semantic` support label is deliberate: the validator cannot establish that a quoted sentence justifies the model's prose. An optional Gemini adapter exists for a future full-text baseline but has not been run because no key or reviewed corpus is available. The local model also cannot currently fit the whole constitution under its configured context budget, so there is no honest full-text local baseline result.

The API exposes `/ask`, `/sources/{id}`, `/health`, and `/version`. The browser displays answer claims as text nodes, opens the exact cited passage on demand, and links to the PDF page. Its short dialogue stores only bounded prior article numbers; each follow-up retrieves current evidence. The local provider has a two-call process-level concurrency limit and one retry for transient failures. Requests log IDs, corpus hash, method, call count, latency, and token usage when available, without logging question text or secrets. This design reduces accidental prompt injection effects because documents have no tools to invoke, but it cannot prove that a model will never echo a malicious instruction in prose.

## 4. Experimental protocol and provisional observations

The planned evaluation has 45 development, 45 validation, and 90 reserved test families in French, with paraphrases in the same family split. Answerable questions need reviewed sufficient evidence spans; ambiguous and out-of-scope questions need reviewed expected behavior without invented gold passages. Three final systems are intended: full text, BM25 RAG, and a pipeline selected on validation. Model, prompt, context budget, abstention policy, and analysis plan must be fixed before opening test results. The current `configs/analysis_plan.json` declares strict success as the primary answer outcome, with family-paired bootstrap intervals. The release gate refuses to mark the project ready without the reviewed corpus, labels, validation selection, frozen systems, and a clean Git revision.

For development only, 15 author-written calibration families were expanded to 45 French questions: direct wording, paraphrase, and one character-deletion typo per family. The labels name relevant articles but no reviewed evidence spans. At Recall@10, BM25S retrieved the labeled article in 44/45 questions, dense search in 41/45, and hybrid in 44/45. Their mean MRR@10 values were 0.879630, 0.619101, and 0.883333 respectively. `reports/french-robustness.md` gives per-variant figures. The tracked questions are in `data/annotations/robustness_calibration.jsonl`, and ignored saved runs are `runs/french-robustness-bm25`, `runs/french-robustness-dense`, and `runs/french-robustness-hybrid`. `constitution-evidence reproduce-retrieval` recalculates every saved score from hits and labels and detected no mismatch in the BM25S and hybrid runs on 2026-10-18. The samples are small, author-written, and derived from unreviewed OCR; they support debugging, not a method ranking for release.

A separate provisional BM25S latency run over 15 direct development questions made 60 retrieval calls without error. Index build took 200.758 ms, the median first-query latency was 0.284 ms over 15 sequential calls, and median warm latency was 0.952 ms over 45 calls at concurrency two. The warm batch has concurrency overhead, so these are not matched cold/warm cache observations. This CPU-only measurement excludes Qwen inference, external APIs, and monetary hardware cost. Its complete observations are in `runs/latency-bm25-20261018/latency.json`. A fixed five-question, three-repeat Qwen variability plan is tracked but has not been executed against a live server.

## 5. Development failure cases

These are retrieval misses against provisional article labels, not audited legal failures. Each is reproducible from the saved 45-question runs and may change after OCR and annotation review.

1. **BM25S, `cal-07-typo`:** “La propiété privée peut-elle être limitée par la loi ?” failed to place labeled article 35 in the top ten. The single-character typo removed a strong lexical cue. Dense and hybrid did retrieve article 35 in this variant.
2. **Dense, `cal-01-paraphrase`:** “Quel droit est protégé par l'article 20 ?” failed to place article 20 in the top ten despite an explicit article number. BM25S and hybrid use direct article lookup and succeeded; this is a case where the simpler path wins.
3. **Dense, `cal-04-paraphrase`:** the domicile and private-exchange paraphrase missed labeled article 24. Hybrid also missed this variant, while BM25S retrieved it. This shows that fusion can displace a useful lexical candidate at a fixed cutoff.
4. **Dense, `cal-10-direct`:** the direct question about arbitrary detention and enforced disappearance missed labeled article 23, while BM25S and hybrid retrieved it. More semantic machinery did not protect this specific direct lookup.
5. **Dense, `cal-13-paraphrase`:** the family-protection paraphrase missed labeled article 32. Both BM25S and hybrid retrieved it. The result identifies a search candidate failure, not whether any subsequent answer would be faithful.

The five cases use only article-level labels. No inspected passage span, model answer, or human judgment is available to classify a citation as sufficient or an answer as wrong. The proper next diagnostic is to review the source PDF and annotate complete evidence, then inspect whether misses arise from OCR, segmentation, ranking, or interpretation.

## 6. Reliability, limits, and next release actions

The repository has offline contract tests for corpus structure, retrieval behavior, citation validation, dialogue isolation, provider retries, API limits, saved-run resumption, blinding, and release gates. These checks cover structural and operational behavior; they do not certify legal accuracy. The publication audit examines tracked files for excluded local payloads and credential patterns. On 2026-10-18 it reported 68 tracked files and no findings. It cannot prove that a third-party license permits redistribution or that a model answer is safe in every case.

The current release-readiness manifest at `runs/release-candidate/manifest.json` is **blocked**. The French corpus is unreviewed; the 45/45/90 reviewed question families, reviewed validation selection, and three fixed final model configurations are missing. No 90-question test run, 270-response blind review, final risk–coverage curve, or `v1.0` tag exists. The clean-clone installation with pinned dependencies and a live Qwen demonstration also remain to be performed on a suitable machine. The reproducibility guide in `docs/reproduction.md` gives the commands and exact gates. A second research extension (J41–J50) should begin only after v1 error categories and a new reserved test justify one narrow hypothesis; no v2 result is claimed here.
