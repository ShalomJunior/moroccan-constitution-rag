# J41–J50 research extension gate

The roadmap places a second contribution after the v1 report and release. It asks for **one** extension chosen from observed failures: adaptive routing between a simple and deeper retrieval/verification path, or reranker adaptation if ranking is the dominant measured error. No reviewed v1 response errors, validated cost/quality curve, or new reserved test currently exists. Choosing, training, or publishing either variant now would turn provisional development observations into an unsupported research claim.

Before J41, require a completed v1 error analysis with counts for retrieval misses, context omissions, unsupported claims, and abstention errors; measured per-path calls/tokens/latency; and a new question-family split that was not opened during v1 selection. Pre-register a falsifiable quality-at-cost target and a maximum call budget. If those inputs are absent, the decision is **defer the extension** and keep the simpler v1 implementation.

If routing is justified, build dev/validation features available at inference time only, such as question length, explicit article references, retrieval scores, and context coverage signals. Do not include gold evidence, answer correctness, or test labels as features. Compare always-simple, always-deep, and routed policies with equal cache conditions, counting router and verifier calls. Use family-grouped validation, document negative results, and freeze a new v2 configuration before a separate test. If reranking is justified instead, collect additional reviewed positive and negative groups before any training; the planned 180 v1 families alone do not establish a reliable training set.

J46 stress tests should modify copies of dev passages only and label them synthetic, keeping the authentic corpus immutable. J48 requires newly reserved families and blind judgments using the same grid. Without that new test, report the extension as exploratory rather than independently validated. J49–J50 reports, figures, presentation, and any `v2` tag depend on those measurements. No v2 branch, model, dataset, or score is claimed in the current development build.
