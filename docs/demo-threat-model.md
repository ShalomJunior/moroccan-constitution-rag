# Demo threat model (J29)

The local demo accepts a browser question, retrieves OCR passages, optionally calls a loopback Qwen server, and returns source-linked text. The relevant untrusted inputs are user questions, OCR text, model output, and source IDs. No retrieved text is executed as a command or used as a URL for server-side requests. The model has no tools. API input limits are 2,000 question characters, 1–20 results, and three short history entries; CLI asks use the same question and result limits. Local model requests are limited to two simultaneous calls per server process, including planning calls. A busy process returns HTTP 429. This is process-local capacity control, not a distributed rate limit.

Model claims require passage IDs and exact quotes with matching hashes and offsets. A fabricated quote or source is rejected. The browser inserts response text with `textContent`, loads passages through the source route, and links only to the configured source PDF. API errors do not include credentials. Keys are read server-side from environment variables; the browser sends no key and receives none. Stored request logs omit question and passage text.

These controls prevent a document instruction from triggering a tool action and prevent fabricated literal citations from passing the structural check. They do not establish that a quoted passage semantically supports a claim, that OCR text is correct, or that every malicious instruction is ignored in the generated prose. The offline safety suite covers long inputs, missing sources, forged quotes, document-instruction text, HTML rendering, and provider failures without contacting a third-party service.
