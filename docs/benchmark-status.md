# État du benchmark v1

`data/annotations/questions.jsonl` contient 45 questions de développement et 45 questions de validation revues par le propriétaire du projet. Le développement reprend les 15 questions de calibration et ajoute 30 questions. Les annotations conservent le hash du corpus corrigé, la provenance de la revue, les statuts, les affirmations attendues et les passages canoniques cités.

La commande `constitution-evidence audit-questions` affiche l'inventaire et les défauts de structure. Elle vérifie notamment les identifiants, la séparation des familles, les champs d'annotation et les offsets des preuves dans le corpus actif. Elle ne peut pas établir qu'une interprétation juridique est correcte. Le seuil prévu est atteint : 45 familles dev, 45 validation et 90 test. Les 90 questions test revues sont conservées dans un fichier **local, ignoré par Git**, `data/annotations/test-candidates.jsonl`. Elles ne doivent pas servir au choix des méthodes.

`constitution-evidence question-review-packet` crée `reports/question-review.md`, un dossier de travail local avec les questions dev, les articles candidats, le texte canonique et les liens vers les pages du PDF. Pour validation, utiliser `constitution-evidence question-review-packet --split validation --output reports/question-review-validation.md`. Le dossier du test local est généré avec `--questions data/annotations/test-candidates.jsonl --split test --output reports/question-review-test.md`. Ces dossiers sont ignorés par Git. Ils servent à contrôler les annotations, sans les modifier automatiquement.

Pour chaque famille ajoutée, suivre [le guide d'annotation](annotation-guide.md), vérifier les preuves sur le PDF et le corpus canonique, puis seulement attribuer `review_status: "reviewed"`. Les 135 questions validation/test ont été accréditées par le propriétaire du projet sur la base d'un audit assisté ; les 45 questions dev proviennent de sa revue transmise. Cela ne constitue pas une double revue indépendante. Les questions test doivent être gelées avant leur exécution ; leurs sorties ne servent pas à choisir les méthodes.

La sélection sur validation, le gel de la configuration, le test réservé et le jugement des réponses sont terminés. Les résultats agrégés et les limites figurent dans le [rapport d'évaluation finale](../reports/final-evaluation.md). Les questions et sorties détaillées du test restent privées ; elles ne doivent pas être utilisées pour sélectionner rétroactivement une nouvelle méthode sur ce même test.
